# ADR-004：兼容基线锁定 0.111.1 与 0.113.1

- 状态：已接受
- 日期：2026-11-19 00:24
- 当时的项目版本：1.1.0
- 相关文件：`9.SRC/RevertRocketPunch/`、`6.SPEC/001-总体规范.md`、`3.DOCS/003-E-111.1与113.1兼容性核验.md`

## 背景

游戏同时存在两个受支持分支：

- 正式版 `0.111.1`，程序集 SHA-256 `3fb1fa1bf0249087b706a5d0f062a60579e2f5b08df4ee477ddd6f2607f654d5`。
- beta 版 `0.113.1`，程序集 SHA-256 `62ECBE91093E1FA862DE4329AAC865209DCB297804CAF0F0520D92D8C0B4A9C3`。

本机当前安装为 0.113.1。参考库留存了两版 `sts2.dll` 与反编译源码。对比结论：

- `RocketPunch.cs` 在 0.111.1 与 0.113.1 逐字节相同，仍为 `AddUntilPlayed(-1)`。
- `CardEnergyCost.SetUntilPlayed`、`CardModel.Description`、`LocString`、`ReleaseInfoManager`、`ModManager`、`OneTimeInitialization` 无影响本 mod 的差异。
- 0.113.1 新增 `ara` 语言，并把 `ara` 放入隐藏语言集合；官方阿拉伯语 `ROCKET_PUNCH.description` 已经写「إلى 0」（降为 0）。
- 0.111.1 与 0.113.1 都支持 `ind`，官方印尼语描述均为「dikurangi 1」（减少 1）。
- 同一份源码分别引用两版 `sts2.dll` 编译均通过，生成的成员引用集合一致。

## 决策

发布用同一份 DLL，以 0.111.1 程序集为编译基线，在 0.113.1 运行。只引用两版都存在的游戏 API。新增 `ind` 文本；`ara` 不切键，直接使用官方文本。

## 备选方案

- **按版本分发两份 DLL**：需要双份构建、双份测试、双份发布，容易产生版本漂移。否决。
- **以 0.113.1 为编译基线**：正式版 0.111.1 用户可能遇到 `MissingMethodException`；且无法用 0.111.1 程序集做最低基线验证。否决。
- **只支持 0.113.1**：正式版用户仍在 0.111.1，违背兼容目标。否决。
- **为 `ara` 增加 mod 文本**：官方文本已经正确，增加键只会多一份维护面。否决。

## 后果

获益：

- 一份发布包覆盖两个分支，降低发布与回归成本。
- 0.111.1 是最低基线，0.113.1 及后续小版本更容易通过静态比对判断风险。

代价与下游规则：

- 每次游戏更新后必须重新比对本 mod 引用的 API，尤其是 `RocketPunch.cs`、`CardEnergyCost.SetUntilPlayed`、`CardModel.Description`、`LocManager`、`ModManager`。
- 新增游戏 API 不得直接引用，除非确认 0.111.1 也存在。
- 发布前必须运行 `8.TEST/CI-CD/verify-version.ps1`，并以 0.111.1 程序集构建。
- 0.111.1 的实机验证由用户切换 Steam 分支后完成；在完成前，兼容结论只能标「0.113.1 已验证、0.111.1 静态验证」。
