# 总体设计：回调火箭飞拳（RevertRocketPunch）

- 版本：1.0（`9.SRC/RevertRocketPunch/RevertRocketPunch.json` 的 `version` 字段）
- 面向游戏版本：`min_game_version = 0.107.0`；仅 `SemVer.Major == 0 && Minor >= 110` 时启用补丁
- 信息出处：`9.SRC/RevertRocketPunch/` 源码、`1.ADR/` 三篇决策记录、`3.DOCS/` 两篇文档、mod 清单

## 1. 设计目标

把游戏卡牌「火箭飞拳」（`RocketPunch`，故障机器人）的触发效果与卡面描述，从 v0.110 起的「生成状态牌 → 费用减少 1」（`AddUntilPlayed(-1)`）回调为 v0.107.1 及之前的「生成状态牌 → 费用降为 0」（`SetUntilPlayed(0)`）。约束：

- 直接在原卡上改行为与文本，不新增卡牌、不禁用原卡。
- 不依赖任何其他 mod；`0Harmony` 与 `sts2` 仅作编译期引用（`Private=false`）。
- 游戏版本低于 0.110 或卡牌不存在时保持原版行为，不报错、不崩溃。
- 只改被点名的两处：效果触发方法与描述文本；卡名、卡图、数值（2 费 / 13(+1) 伤害 / 抽 1(+1)）不动。

## 2. 模块划分与职责

| 模块 | 文件 | 职责 |
|---|---|---|
| 入口 | `ModEntry.cs` | `[ModInitializer("ModLoaded")]` 标注的静态入口；创建 `Harmony("RevertRocketPunch")` 实例，`PatchAll` 当前程序集；整体 try/catch，异常记 `Log.Error` |
| 总开关 | `ModConfig.cs` | `IsReplaceEnabled` = 卡存在性守卫通过 且 版本门通过；`IsActiveVersion()` 懒求值 + 缓存，`SemVer` 未就绪时暂放行（下次再评估） |
| 卡存在性守卫 | `Patches/RocketPunchGuard.cs` | `IsSupported()` 运行时调用 `ModelDb.Card<RocketPunch>()`；成功缓存 `true` 并记日志；失败仅告警一次（`_warned`）并放行、不缓存 |
| 效果补丁 | `Patches/RocketPunchGeneratedStatusPatch.cs` | `[HarmonyPatch(typeof(RocketPunch), "AfterCardGeneratedForCombat")]` 的 Prefix，命中即 `SetUntilPlayed(0)` 并短路 |
| 文本补丁 | `Patches/RocketPunchTextPatch.cs`（类名 `RocketPunchDescriptionPatch`） | `CardModel.Description` getter 的 Postfix；对 `RocketPunch` 实例且语言受支持时，把结果换成 `LocString("cards", "RE_ROCKET_PUNCH.description")` |
| 资源 | `RevertRocketPunch/localization/<lang>/cards.json`、`RevertRocketPunch/mod_image.png` | 15 语言 `RE_ROCKET_PUNCH.description` 文本；占位图标。由 `export_presets.cfg` 显式清单打进 pck |
| 清单 | `RevertRocketPunch.json` | `id=RevertRocketPunch`、`version=1.0`、`has_dll/has_pck=true`、`min_game_version=0.107.0`、`affects_gameplay=true` |
| 构建 | `build.ps1` | `dotnet build -c Debug` → Godot `--headless --import` → `--export-pack "Windows Desktop"` → 拷贝 dll/pdb/json 到游戏 `mods/RevertRocketPunch/` |

依赖方向是单向的：`ModEntry` → 补丁类；补丁类 → `ModConfig` → `RocketPunchGuard`。补丁类之间互不引用。

## 3. 补丁策略

### 3.1 效果补丁（全路径短路）

```
Prefix(RocketPunch __instance, CardModel card, Player? creator, ref Task __result)
  if (!ModConfig.IsReplaceEnabled) return true;            // 放行原版实现
  if (creator != __instance.Owner
      || card.Owner != __instance.Owner
      || card.Type != CardType.Status)
      { __result = Task.CompletedTask; return false; }     // 等价于 107 守卫分支
  __instance.EnergyCost.SetUntilPlayed(0);                 // 107 效果
  __result = Task.CompletedTask; return false;
```

三重守卫（生成者、牌主、牌类型为 `Status`）与 107 原版一致；补丁体自包含，不调用原方法。这样在 110+ 上无论原实现如何改写降费数值，结果都固定为「绝对费用 0，直至打出」。

### 3.2 文本补丁（切键）

不复写官方键 `ROCKET_PUNCH.description`，而是新增模组专属键 `RE_ROCKET_PUNCH.description`，由 Postfix 在 getter 返回后替换 `LocString`。理由：与同样覆写官方键的 mod（如 CustomCardBalance）不发生 patch 顺序竞争（ADR-001）。

语言白名单：`deu/eng/esp/fra/ita/jpn/kor/pol/ptb/rus/spa/tha/tur/zhs/zht`。`ind` 不在白名单——该语言 107 无官方文本，切键会触发缺失键异常，因此保持官方 111 文案、但效果仍被替换。

### 3.3 版本门与守卫的次序

`IsReplaceEnabled` 每次被补丁调用时求值：先卡存在性（懒求值 + 缓存），再版本门（懒求值 + 缓存）。`SemVer` 读不到或未就绪时「暂按生效放行」，下次访问重试；一旦取到确定版本就固化结论。低于 0.110 的版本上补丁仍会安装，但所有路径返回 `true`，等于原版行为。

## 4. 数据流

```
游戏生成状态牌
   └─ RocketPunch.AfterCardGeneratedForCombat(...)
        └─ Harmony Prefix
             ├─ ModConfig.IsReplaceEnabled
             │    ├─ RocketPunchGuard.IsSupported() → ModelDb.Card<RocketPunch>()
             │    └─ ModConfig.IsActiveVersion()   → ReleaseInfoManager.Instance.SemVer
             ├─ 守卫不通过 → 原版实现（110 以下为减 1）
             └─ 守卫通过 → SetUntilPlayed(0) → 卡费用 = 0（至打出）

卡面渲染
   └─ CardModel.Description (getter)
        └─ Harmony Postfix（RocketPunch 实例 + 受支持语言）
             └─ LocString("cards", "RE_ROCKET_PUNCH.description") → 从 pck 内 cards.json 取文案
```

## 5. 异常处理与降级

| 场景 | 行为 |
|---|---|
| `PatchAll` 抛异常（如游戏类型改名/删除） | `ModEntry` 捕获并 `Log.Error`，游戏不崩溃，补丁整体未安装 → 原版行为 |
| `ModLoaded` 阶段 `ModelDb` 未就绪 | 设计上禁止在 `ModLoaded` 访问 `ModelDb`（ADR-002）；所有 `ModelDb`/`SemVer` 访问都在补丁运行时首次触发时进行 |
| `ModelDb.Card<RocketPunch>()` 失败 | 告警一次，放行且不缓存，下次触发再试；不拦游戏流程 |
| 语言不在白名单（`ind`） | 不切键，显示官方 111 文案，不抛异常 |
| 版本读不到 | 暂按生效处理并重试，不崩溃 |

## 6. 兼容策略

- `min_game_version = 0.107.0`：0.103.2 及更早的 `AfterCardGeneratedForCombat(CardModel, bool)` 签名不同，由加载器原生排除。
- 版本门只认 `Major == 0 && Minor >= 110`；107/108/109 已是目标效果，不干预；110 以后（含 0.111.x）一律修正。
- 目标方法签名在 107/110/111 一致，单份产物三版本通用（证据见 `3.DOCS/001-E-火箭飞拳版本差异与回调可行性.md`）。
- 不保证与盗版、修改版、移动版、老旧版本、冷门 mod 的兼容（`description/` 声明）。

## 7. 构建与测试方案

构建（`build.ps1`）：

1. `dotnet build RevertRocketPunch.csproj -c Debug`（Godot.NET.Sdk/4.5.1 + net9.0，`NoWarn MSB3270`）。
2. Godot 4.5.1 mono console `--headless --import --path <工程>` 生成导入元数据。
3. `--headless --export-pack "Windows Desktop" <mods>/RevertRocketPunch/RevertRocketPunch.pck`；导出清单由 `export_presets.cfg` 显式列出 15 个 `cards.json` 与 `mod_image.png`。
4. 拷贝 dll / pdb / json 到 `C:/Game/Steam/steamapps/common/Slay the Spire 2/mods/RevertRocketPunch/`。

验证（计划文档 §5 的清单）：产物齐全、mods 菜单可见可启用、对局内生成状态牌后费用归 0、禁用 mod 后恢复减 1、卡面文案与效果一致、图鉴与对局文本一致、日志无 Error。**实机验证结论未记录**；仓库内没有自动化测试，也没有 E2E 测试。

## 8. 已知限制

- `ind` 描述未替换（107 无该语言文本）。
- `zht` 无 107 官方文本，采用 111 官方繁中句式改写。
- card 文本依赖关卡自身 `DynamicVars` 渲染 13/14 伤害与 1/2 抽牌，与 111 相同，未写死数值。
- 文档中记录的 v1.0.1 / v1.0.2 为构建标记，manifest `version` 始终为 `1.0`（版本号未递增，见 `5.ChangeLog/001-1.0-2026-08-21.md` 与施工报告）。
