# Mod 运行时初始化时序（111 实证，可复用）

来源：`decompiled-111/MegaCrit.Sts2.Core.Helpers/OneTimeInitialization.cs` + `MegaCrit.Sts2.Core.Modding/ModManager.cs`。

## 启动时序

| 阶段 | 发生的事 | Mod 可访问性 |
|---|---|---|
| `ExecuteVeryEarly` | `SaveManager.InitSettingsData` → **`ModManager.Initialize()`**（读 mods 目录、`TryLoadMod` → **`CallModInitializer` → ModLoaded 在此被调用**） | ⚠️ ModelDb/LocManager 均未初始化 |
| `ExecuteEssential` | `LocManager.Initialize()` → `AssemblyInfo.Init()` → **`ModelDb.Init()`** → `InitIds()` | ModelDb 就绪 |
| `ExecuteDeferred` | `ModelDb.Preload()`（非编辑器）等 | 可正常使用 |

## 铁律

1. **ModLoaded 阶段禁止访问 ModelDb 与 LocManager**（它们晚于 ModLoaded 初始化）。访问必然抛异常（如 `ModelDb.Card<T>()` 对空字典抛 `KeyNotFoundException`）。
2. 与运行期状态相关的检查（卡存在性、ModelDb 内容）一律放到**补丁运行时首次触发时懒评估**——那时游戏早已进入主菜单/对局，ModelDb 必然就绪。
3. 参考实现：回调王座 `SealedThroneShapeGuard.IsSupported()`（运行时 ModelDb 检查 + 失败暂放行不缓存）；回调同步 ModLoaded 只做静态反射检查（AccessTools），从不访问 ModelDb。

## 反例（本系列实际踩坑，见 ADR-002）

RevertRocketPunch v1.0：`ModLoaded` 里 `ModelDb.Card<RocketPunch>()` 必然 KeyNotFound → 误判「卡不存在」→ 跳过 `Harmony.PatchAll` → 补丁一个都没装 → mod 显示已加载但完全无效果。修复：ModLoaded 无条件 PatchAll，存在性检查移入 `RocketPunchGuard.IsSupported()` 懒评估。
