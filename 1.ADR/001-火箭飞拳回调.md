# ADR-001：RevertRocketPunch —— 火箭飞拳回调至 v0.110 之前效果

- 日期：2026-08-20
- 状态：已记录（v1.0 构建安装；v1.0.1 修复 ModelDb 访问时机 bug 后重建，见 ADR-002；待实机验证）
- 关联计划：`2.PLANS/001-G-火箭飞拳回调计划.md`

## 背景

v0.110 起，故障机器人卡牌「火箭飞拳」的触发降费从「生成状态牌 → 费用降为 0」（`SetUntilPlayed(0)`，107 及之前）削弱为「生成状态牌 → 费用减少 1」（`AddUntilPlayed(-1)`）。需求：回调为 107 效果（用户表述「110 版本之前的效果」）。

## 决策

1. **单点效果补丁**：Prefix 全路径短路 `RocketPunch.AfterCardGeneratedForCombat`，命中「卡主生成状态牌」时 `EnergyCost.SetUntilPlayed(0)`，其余分支与 107 守卫语义一致；补丁体自包含、不读原版实现（沿用 CustomCardBalance 已验证写法）。
2. **文本切键（RE_ 前缀）**：`RE_ROCKET_PUNCH.description` 走 `CardModel.Description` getter 切键，避免与其他 mod（如 CustomCardBalance）对官方键 `ROCKET_PUNCH.description` 的覆写冲突；标题不改（`ROCKET_PUNCH.title` 保持不变）。
3. **卡存在性检查（替代形状守卫）**：运行时 `ModelDb.Card<RocketPunch>()` 存在性检查，未来版本删卡 → 补丁禁用 + Log.Warn，不崩溃；不做静态形状守卫（用户决策 2026-08-20，与「同步」回调的深度守卫不同——火箭飞拳回调仅单点、风险面小，卡存在即可工作）。
4. **版本门**：`SemVer.Minor >= 110` 才生效；107/108/109 已是目标效果不干预；110+ 一律修正（面向未来版本）。懒求值 + 缓存，未就绪暂放行。
5. **版本门槛**：manifest `min_game_version=0.107.0`。
6. **不回调项**：`OnPlay` 的 `FromCard(this)`→`FromCard(this, cardPlay)` 仅为 110 起 API 签名扩展，无玩家可见效果差异，不动。
7. **素材**：不改卡图；pck 仅 16×cards.json + 占位 `mod_image.png`（复用系列生成脚本）。

## 备选方案与放弃原因

- 直接覆写官方键 `ROCKET_PUNCH.description`（CustomCardBalance 模式，纯 DLL 免 pck）：与同覆写该键的 mod 存在 Harmony patch 顺序竞争，弃用。
- 不做版本门（全版本生效）：107 上重复设置 Absolute 修饰符虽幂等，但属无谓干预，弃用。
- 版本门用加载器分支（PlatformBranch）：110/111 同属 beta 分支无法区分，弃用（同回调同步先例）。

## 影响

- 110/111/未来版本上，「火箭飞拳」被固定为 107 定义（生成状态牌 → 费用归零 + 107 文案）。
- 107 及更早（≥0.107.0）上 mod 完全惰性（补丁不生效）。
- 未来游戏改动 RocketPunch 结构 → 守卫降级禁用补丁，按 docs 维护清单回归。
